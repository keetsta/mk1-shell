# MK-1: чип и шелл визитки

внутренняя спека, со спойлерами. игрок видит только мануал из `content/`, побитый.

## идея

- **shenzhen i/o:** короткая программа под выдуманный чип с жёсткими лимитами (24 инструкции, сторож на 128 инструкций без `wait`), задачу проверяют тесты, счёт ведут в инструкциях и тактах.
- **blackbox cup:** документация неполная и побитая (`▒`). чего нет в мануале, игрок выясняет опытами: `try` сразу выполняет одну инструкцию на карте (светодиоды загораются), `regs` показывает, что осталось в регистрах.
- **главы:** каждая решённая задача открывает следующую главу мануала, а в ней новые инструкции, порты и следующая задача.

## чип

| что | значение |
|---|---|
| слово | 16 бит, 0..65535, арифметика по модулю 65536 |
| регистры | `a b c d`, флаг `f` (ставят `eq lt gt`, читают `jt jf`) |
| программа | до 24 инструкций, метки `имя:`, комментарий `#` или `;`, регистр букв не важен |
| числа | `42`, `0x2a`, `0b101010`, `-1` (= 65535) |
| время | тик 20 мс. программа выполняется, пока не скажет `wait`, потом спит |
| сторож | 128 инструкций за тик без `wait` = ошибка |
| конец | выполнение после последней строки = `halt` |

инструкции (`x` значение: регистр, порт или число; `d` регистр или порт на запись; `l` метка):

| инструкция | действие |
|---|---|
| `mov x d` | d = x |
| `add sub mul x d` | d = d ± × x, младшие 16 бит |
| `div x d` | d = d / x с округлением вниз, x = 0 даёт ошибку |
| `and or xor x d` | побитово |
| `not d` | инверсия |
| `shl shr n d` | сдвиг, n ≥ 16 даёт 0 |
| `rev d` | разворот 16 бит (бит 15 ↔ бит 0) |
| `cnt x d` | d = число единичных бит в x |
| `eq lt gt x y` | f = x == y, x < y, x > y (без знака) |
| `jmp jt jf l` | переход всегда, при f = 1, при f = 0 |
| `wait n` | спать n тиков (0 = 1) |
| `nop`, `halt` | |

порты:

| порт | доступ | что |
|---|---|---|
| `btn` | чтение | кнопка, 1 пока нажата |
| `lux` | чтение | датчик света, 0..1023 |
| `clk` | чтение | тики с запуска |
| `rnd` | чтение | xorshift16, новое число на каждое чтение |
| `row` | чтение, запись | строка экрана для `pix`, 0 сверху |
| `pix` | чтение, запись | 16 светодиодов строки `row`, бит 15 слева. при `row` ≥ 9 запись теряется |
| `ea` | чтение, запись | адрес в U7 (8 бит) |
| `ed` | чтение, запись | байт U7 по адресу `ea`, после чтения и записи `ea` + 1 |

назначение в `add`, `sub` и т.п. читается без побочных эффектов: `add 1 ed` прибавит к байту по текущему адресу, а адрес сдвинется один раз, при записи.

## задачи и главы

- задача кормит программу сегментами по 30..79 тиков: в каждом своё состояние кнопки и свой уровень света. выходы (9 строк экрана) снимаются в конце сегмента, поэтому точный тайминг не важен, важна реакция за время сегмента. снимок кончается двумя нулевыми байтами, местом пищалки, которой на карте больше нет: они входят в каждый ответ, и без них сменились бы ключи всех глав.
- снимки сцепляются в хеш: `h_i = sha256("mk1/smp" | h_(i-1) | снимок_i)`. в прошивке лежат только первые 4 байта `sha256("mk1/chk" | h_i)` на каждый снимок: их хватает, чтобы сказать «тест 3 из 10 не прошёл», но не чтобы узнать правильный экран.
- ответ задачи `h_n`. следующая глава зашифрована ключом `sha256("mk1/key" | h_n)` (поток `sha256("mk1/txt" | ключ | счётчик)`). ни ответов, ни текста глав в прошивке нет. обойти можно, только переписав чип и решив задачу на нём, и такое читерство мы разрешаем.
- задача k описана в главе k−1, её решение открывает главу k.

**контент приватный.** `content/` (тексты глав и эталонные решения `solN.asm`) живёт в отдельном приватном репозитории `keetsta/mk1-content` и клонируется в `content/` (папка в `.gitignore`): по нему читается весь мануал. сюда идёт только сгенерированный `src/core/content_gen.c`. `make content` пересобирает его и проверяет, что каждое эталонное решение проходит свою задачу.

## шелл

`help man tasks task edit list run check top try regs cls`. стрелки ↑ ↓ листают 16 последних команд (строки программы из `edit` туда не попадают). история живёт в ОЗУ и пропадает с выключением карты. ctrl-d в пустой строке: «bye» и `hal_exit` (эмулятор закрывается, карта уходит в режим ожидания). `man` листает главу по экрану, если `hal_rows` говорит, сколько строк видно (в эмуляторе: высота области под панелью; на карте 0, там терминал сам листается назад). ← → двигают курсор в строке, работают home, end, delete, ctrl-a, ctrl-e. ввод только ASCII. `objdump`, `gdb`, `hexdump` и `sudo` с любыми аргументами печатают «there will be dragons!» и пускают эту фразу бегущей строкой по матрице. в `help` их нет.

между включениями сохраняются ключи открытых глав, текущая задача, текст программы и лучшая программа каждой решённой задачи (для доски, ниже). состояние прошивки до доски, без программ, загружается как было: главы остаются открытыми, а задачи, решённые на ней, для доски надо проверить ещё раз. состояние не больше `HAL_STATE_MAX` (4080 байт): карта держит его в одном секторе флеша, а больше молча не сохранила бы.

## протокол страницы

страница keetsta.me/mk1 говорит с картой по тому же USB-порту, что и терминал, через OSC-последовательности: их xterm.js на странице перехватывает и не показывает, а в `screen` они не приходят вовсе, пока страница не поздоровалась.

- страница → карта: `ESC ] 7777 ; hello BEL` включает режим страницы, `ESC ] 7777 ; bye BEL` выключает. закрывать можно и `ESC \`.
- карта → страница: в ответ на hello `ESC ] 7777 ; mk1 ; 2 ; <версия прошивки> BEL` (протокол 2, прошивка `MK1_VERSION` из `shell.h`, у релиза тег `v<версия>`) и сразу текущий кадр. дальше кадр на каждое изменение экрана: `ESC ] 7777 ; f ; <144 hex-цифры> BEL`, по цифре на светодиод (яркость 0..f, как её видит глаз), строка 0 первой, слева направо. при 50 кадрах в секунду это меньше 8 КБ/с.
- кадр это то, что горит на карте, а не матрица шелла: ожидание, кубик, переходы и послесвечение тоже, а в демо-прошивке и понг. что на экране, ядру говорит платформа через `shell_screen` (карта: каждый тик, после `face_render`), а где экран и есть матрица шелла (хост, тесты), она возвращает её через `shell_screen_rows`. протокол 1 возил 9 строк по 4 hex-цифры, только матрицу шелла: страница понимает оба.
- OSC вырезаются из ввода в любом режиме (строка, `edit`, `run`, листание). на физической карте после hello идёт `7777;chip;<chipid>`. при отключении парсер сбрасывает незаконченные команды.
- смена ника идёт через `7777;nick;<nonce>;<hex utf-8 ника>`. ответ содержит nonce и HMAC-SHA256 над доменом `mk1/board-nickname/v1\0`, chip id, nonce и байтами ника. сервер выдаёт nonce на две минуты и принимает его один раз.
- прошивка карты зовёт `shell_connect()`, когда поднимается DTR: всё, что шелл печатал раньше, ушло в никуда, поэтому баннер и текущая строка печатаются заново, и `screen` сразу видит приглашение.
- прошивка карты зовёт `shell_disconnect()`, когда падает DTR: окно закрыли, кадры больше некому слать.
- прошивка через страницу: для карты, представившейся по протоколу и приславшей chip id, сайт просит перезапуск на 1200 бод. пользователь выбирает загрузчик WebUSB, сайт сверяет его серийный номер с chip id. старые карты переводятся в BOOTSEL кнопкой и требуют отдельного подтверждения после выбора. перед стиранием проверяется весь образ, после записи каждый сектор сверяется чтением.

## что побито в мануале сейчас

- глава 0: `gt` (f = x > y), `jf` (при f = 0), бит 0 в `pix` (правый светодиод), что делает сторож (останавливает программу с ошибкой).
- глава 1: `xor`, `shl` на 16 и больше (0), `div` на 0 (ошибка), `rev`, `cnt`, `rnd` («случайное»), `ea`, `ed`.

## лидерборд и голы

- задачи двух видов: обычные, без баллов (как сейчас: решение открывает следующую главу), и **голы** — цели с баллами.
- после первой решённой задачи команда `top` печатает ссылку с токеном, по ней игрок добавляет себя в лидерборд на сайте. баллы за голы видны в лидерборде.

схема:
- **токен несёт решения, а не баллы.** в нём лучшие программы карты (байткод, до 24 инструкций на задачу) и id карты. сервер прогоняет их на том же ядре в wasm и сам считает баллы. токен подписывает ключ конкретной карты. проверка подтверждает прохождение присланных программ по тестам и ключ карты. авторство программы и сборка прошивки за пределами этой проверки.
- **личность карты (решено).** на доске только официальные карты. личность выдаёт только автор: заносит карту в таблицу на сервере, когда её собирает. заливка прошивки личность не создаёт (mk1-web шьёт любому), поэтому роллить её нельзя: личностей ровно столько, сколько карт в таблице.
  - ключ карты выводится из заводского `RANDID`: 128 случайных бит в OTP (строки 0x004..0x00b), у каждого чипа свои. при сборке их читает picotool в BOOTSEL, в таблицу идёт `chipid → ключ`. шелл подписывает токен HMAC-SHA256.
  - своя прошивка OTP не стирает: карта остаётся собой, восстанавливать нечего. своя прошивка тоже может подписать токен, но только от имени этой же карты.
  - что остаётся: кто держит карту в руках, может скопировать её личность (RANDID читается через BOOTSEL). ключ не сменить, утёкшую карту можно только отозвать. утечка таблицы позволяет выдавать себя за уже занесённые карты, новые так не создать.
  - secure boot не включаем: он необратим, и карта перестанет брать свой `.uf2`.
  - одна карта уже роздана без записи в таблице: её автор заносит вручную.
- **формат токена (сделано в прошивке, `src/core/token.h`).** ссылка `https://keetsta.me/mk1/top#<токен>`, токен: base64url без `=` от `1 | chipid[8] | записи | mac[16]`.
  - запись: номер задачи, длина, программа в байтах. записи по возрастанию номера задачи, одна на задачу.
  - программа в байтах (`vm_encode`): опкод, потом операнды по порядку: регистр 0x00..0x03, порт 0x10 + номер, число 0x20 и два байта старшим вперёд, цель перехода номером инструкции (номер, равный длине программы, это её конец: метка после последней строки).
  - mac: первые 16 байт HMAC-SHA256(ключ карты, всё перед ним). ключ карты = sha256(`"mk1/card"` | RANDID).
  - порядок байтов: chipid как в серийном номере USB (`FA38…2B` это байты fa 38 … 2b), RANDID это ряды 0x004..0x00b по порядку, в каждом младший байт первым.
  - пример (выдуманный, его проверяет тест): RANDID 00 01 … 0f даёт ключ `edea6373…6030fd22`, а chipid 01..08 с записями `01 02 12 13 02 01 12` дают токен `AQECAwQFBgcIAQISEwIBEjgNJk0vwWidoANKpOWPoWc`.
  - сервер разбирает программы только через `vm_decode`: он пропускает ровно те байты, что `vm_encode` делает из собранной программы. исполнитель чипа номера регистров и портов не проверяет, поэтому чужие байты в обход декодера не исполнять.
  - ключ и RANDID нигде не печатаются: ни шеллом, ни инструментами.
- **баллы дают только голы.** обычная задача — «прошёл / не прошёл». гол считает баллы, например как в shenzhen i/o: меньше инструкций и тактов, чем у эталона, — больше баллов. или открытый счёт без потолка.
- **прошивка** хранит лучшую программу каждой решённой задачи вместе с ключами глав (сделано, до 1500 байт на все программы). лучшая сейчас короче, а при равной длине быстрее (меньше тактов): это временный порядок, пока не решено, как гол считает баллы. для сравнения карта прогоняет хранимую программу заново. голы будут храниться так же.
- **ссылка** `keetsta.me/mk1/top#<токен>`: токен во фрагменте, на сервер он уходит только кнопкой со страницы. если карта подключена к странице, решения можно забрать прямо с неё.
- **флуд:** одна запись на карту по id чипа, лучший результат сохраняется. при публикации можно задать первый ник. установленный ник меняется после одноразового подтверждения карты. лимиты действуют на запросы по IP и на новые проверки программ по карте.
- **бэкенд (решено):** сервис на localhost принимает `/mk1/api/leaderboard` через Caddy. SQLite хранится вне корня сайта. карты регистрируются командой через ssh. лимит публикаций использует `CF-Connecting-IP`: Caddy принимает его от Cloudflare, а для остальных соединений подставляет адрес клиента.

решить: (1) как гол считает баллы: эффективность решения, открытый счёт или и то и другое; (2) что делать со списыванием: ключ карты не мешает набрать на своей карте чужую программу. решения из try it на доску не попадают: у них нет ключа карты.

## открыто

1. название и легенда чипа. рабочее имя MK-1, как у карты. язык мануала: сейчас английский, как всё на плате.
2. задачи 3..12 с сюжетом. U7 «чёрный ящик»: порты `ea`/`ed` есть, задач на них пока нет.
3. сборка под RP2350: сделана в `src/card/` (USB CDC, IS31FL3731, датчик света, флеш, экраны без терминала: ожидание с адресом, заставки по очереди случайно (кубик, маятники, осциллограф, лава, жизнь), сон; при заливке со страницы матрица крутит «течение»). понг и кубик по удержанию живут в демо-прошивке `demo/`. без терминала кнопка основной прошивки будит карту и пускает адрес. реверс показывает шелл бегущей строкой.
4. редактор: программа вводится только целиком. правка строки по номеру пока не сделана.
5. лидерборд и голы: подпись и `top` в прошивке, регистрация и бэкенд в `server/`, страница в mk1-web. текущие задачи дают ноль очков. результаты ранжируются по очкам и числу решённых задач, затем по инструкциям, тактам, тикам и времени. для запуска на VDS см. `server/README.md`. каталог голов и формула баллов остаются открытыми.
