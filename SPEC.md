# MK-1: чип и шелл визитки

внутренняя спека, со спойлерами. игрок видит только мануал из `content/`, побитый.

## идея

- **shenzhen i/o:** короткая программа под выдуманный чип с жёсткими лимитами (24 инструкции, сторож на 128 инструкций без `wait`), задачу проверяют тесты, счёт ведут в инструкциях и тактах.
- **blackbox cup:** документация неполная и побитая (`▒`). чего нет в мануале, игрок выясняет опытами: `try` сразу выполняет одну инструкцию на карте (светодиоды загораются), `regs` показывает, что осталось в регистрах.
- **главы:** каждая решённая задача открывает следующую главу мануала, а в ней новые инструкции, порты и следующая задача.

## чип

| что | значение |
|---|---|
| слово | 16 бит, 0..65535, арифметика по модулю 65536 |
| регистры | `a b c d`, флаг `f` (ставят `eq lt gt`, читают `jt jf`) |
| программа | до 24 инструкций, метки `имя:`, комментарий `#` или `;`, регистр букв не важен |
| числа | `42`, `0x2a`, `0b101010`, `-1` (= 65535) |
| время | тик 20 мс. программа выполняется, пока не скажет `wait`, потом спит |
| сторож | 128 инструкций за тик без `wait` = ошибка |
| конец | выполнение после последней строки = `halt` |

инструкции (`x` значение: регистр, порт или число; `d` регистр или порт на запись; `l` метка):

| инструкция | действие |
|---|---|
| `mov x d` | d = x |
| `add sub mul x d` | d = d ± × x, младшие 16 бит |
| `div x d` | d = d / x с округлением вниз, x = 0 даёт ошибку |
| `and or xor x d` | побитово |
| `not d` | инверсия |
| `shl shr n d` | сдвиг, n ≥ 16 даёт 0 |
| `rev d` | разворот 16 бит (бит 15 ↔ бит 0) |
| `cnt x d` | d = число единичных бит в x |
| `eq lt gt x y` | f = x == y, x < y, x > y (без знака) |
| `jmp jt jf l` | переход всегда, при f = 1, при f = 0 |
| `wait n` | спать n тиков (0 = 1) |
| `nop`, `halt` | |

порты:

| порт | доступ | что |
|---|---|---|
| `btn` | чтение | кнопка, 1 пока нажата |
| `lux` | чтение | датчик света, 0..1023 |
| `clk` | чтение | тики с запуска |
| `rnd` | чтение | xorshift16, новое число на каждое чтение |
| `row` | чтение, запись | строка экрана для `pix`, 0 сверху |
| `pix` | чтение, запись | 16 светодиодов строки `row`, бит 15 слева. при `row` ≥ 9 запись теряется |
| `bz` | чтение, запись | пищалка, Гц, 0 = тишина |
| `ea` | чтение, запись | адрес в U7 (8 бит) |
| `ed` | чтение, запись | байт U7 по адресу `ea`, после чтения и записи `ea` + 1 |

назначение в `add`, `sub` и т.п. читается без побочных эффектов: `add 1 ed` прибавит к байту по текущему адресу, а адрес сдвинется один раз, при записи.

## задачи и главы

- задача кормит программу сегментами по 30..79 тиков: в каждом своё состояние кнопки и свой уровень света. выходы (9 строк экрана и `bz`) снимаются в конце сегмента, поэтому точный тайминг не важен, важна реакция за время сегмента.
- снимки сцепляются в хеш: `h_i = sha256("mk1/smp" | h_(i-1) | снимок_i)`. в прошивке лежат только первые 4 байта `sha256("mk1/chk" | h_i)` на каждый снимок: их хватает, чтобы сказать «тест 3 из 10 не прошёл», но не чтобы узнать правильный экран.
- ответ задачи `h_n`. следующая глава зашифрована ключом `sha256("mk1/key" | h_n)` (поток `sha256("mk1/txt" | ключ | счётчик)`). ни ответов, ни текста глав в прошивке нет. обойти можно, только переписав чип и решив задачу на нём, и такое читерство мы разрешаем.
- задача k описана в главе k−1, её решение открывает главу k.

**контент приватный.** `content/` (тексты глав и эталонные решения `solN.asm`) не публикуется: по ним читается весь мануал. в репозиторий идёт только сгенерированный `src/core/content_gen.c`. `make content` пересобирает его и проверяет, что каждое эталонное решение проходит свою задачу.

## шелл

`help man tasks task edit list run check try regs cls`. стрелки ↑ ↓ листают 16 последних команд (строки программы из `edit` туда не попадают). история живёт в ОЗУ и пропадает с выключением карты. ctrl-d в пустой строке: «bye» и `hal_exit` (эмулятор закрывается, карта уходит в режим ожидания). `man` листает главу по экрану, если `hal_rows` говорит, сколько строк видно (в эмуляторе: высота области под панелью; на карте 0, там терминал сам листается назад). ← → двигают курсор в строке, работают home, end, delete, ctrl-a, ctrl-e. ввод только ASCII. `objdump`, `gdb`, `hexdump` и `sudo` с любыми аргументами печатают баннер (дракон и крупная надпись «there will be dragons!») и пускают эту фразу бегущей строкой по матрице. в `help` их нет.

между включениями сохраняются ключи открытых глав, текущая задача и текст программы.

## протокол страницы

страница keetsta.me/mk1 говорит с картой по тому же USB-порту, что и терминал, через OSC-последовательности: их xterm.js на странице перехватывает и не показывает, а в `screen` они не приходят вовсе, пока страница не поздоровалась.

- страница → карта: `ESC ] 7777 ; hello BEL` включает режим страницы, `ESC ] 7777 ; bye BEL` выключает. закрывать можно и `ESC \`.
- карта → страница: в ответ на hello `ESC ] 7777 ; mk1 ; 1 ; <версия прошивки> BEL` (протокол 1, прошивка `MK1_VERSION` из `shell.h`, у релиза тег `v<версия>`) и сразу текущий кадр. дальше кадр на каждое изменение матрицы или пищалки: `ESC ] 7777 ; f ; <9 строк по 4 hex-цифры, строка 0 первой> ; <пищалка, Гц> BEL`. при 50 кадрах в секунду это меньше 3 КБ/с.
- OSC вырезаются из ввода в любом режиме (строка, `edit`, `run`, листание) и до клавиш не доходят. чужие и длиннее 39 символов отбрасываются.
- прошивка карты зовёт `shell_disconnect()`, когда падает DTR: окно закрыли, кадры больше некому слать.
- прошивка через страницу: страница открывает порт на 1200 бод, прошивка карты на это перезагружается в BOOTSEL, дальше страница шьёт через WebUSB (PICOBOOT). это делает прошивка карты, не ядро.

## что побито в мануале сейчас

- глава 0: `gt` (f = x > y), `jf` (при f = 0), бит 0 в `pix` (правый светодиод), что делает сторож (останавливает программу с ошибкой).
- глава 1: `xor`, `shl` на 16 и больше (0), `div` на 0 (ошибка), `rev`, `cnt`, `rnd` («случайное»), `ea`, `ed`.

## лидерборд и голы (план, не начато)

запрос пользователя, 2 ноября 2026:
- задачи двух видов: обычные, без баллов (как сейчас: решение открывает следующую главу), и **голы** — цели с баллами.
- когда все задачи решены, шелл выдаёт ссылку и токен, по ним игрок добавляет себя в лидерборд на сайте. токен складывается из баллов за голы, баллы видны в лидерборде. от флуда надо защитить.

предложенная схема (ждёт решений ниже):
- **токен несёт решения, а не баллы.** в нём лучшие программы карты (байткод, до 24 инструкций на задачу) и id карты. сервер прогоняет их на том же ядре (wasm, как try it) и сам считает баллы. подписать токен секретом нельзя: прошивка публичная, секрет из неё вытащат. а так подделать токен можно, только написав работающие программы, то есть пройдя игру.
- **баллы дают только голы.** обычная задача — «прошёл / не прошёл». гол считает баллы, например как в shenzhen i/o: меньше инструкций и тактов, чем у эталона, — больше баллов. или открытый счёт без потолка.
- **прошивка** хранит лучшее решение каждой задачи и каждого гола вместе с ключами глав.
- **ссылка** `keetsta.me/mk1/top#<токен>`: токен во фрагменте, на сервер он уходит только кнопкой со страницы. если карта подключена к странице, решения можно забрать прямо с неё.
- **флуд:** мусор отсекает перепроверка. одна запись на карту по id чипа, повторная отправка её заменяет. лимит по IP, ручное удаление записей.
- **бэкенд:** сайт статический, нужен маленький сервер. рекомендация: Cloudflare Worker + D1 (сайт и так за Cloudflare, wasm-ядро в Worker запускается как есть). запасной вариант: сервис на своём сервере за Caddy.

решить: (1) где бэкенд; (2) как гол считает баллы: эффективность решения, открытый счёт или и то и другое; (3) засчитывать ли решения из try it без карты.
