# бэкенд лидерборда mk-1

нужны node.js 24 и zig. проверяющий wasm собирается из ядра прошивки и публичного `content_gen.c`.

```sh
install -d -m 700 "$HOME/.local/share/mk1-board"
node server/build-score.mjs
node server/main.mjs
```

сервис слушает `127.0.0.1:8787`. `MK1_BOARD_PORT` меняет порт, `MK1_BOARD_DB` задаёт абсолютный путь к sqlite вместо `~/.local/share/mk1-board/leaderboard.sqlite`. каталог базы держи вне корня сайта. сервис и ssh-команда регистрации должны работать от одного пользователя с одним путём к базе.

прокси сайта передаёт `/mk1/api/leaderboard` сервису с исходным путём. на VDS включи `MK1_BOARD_TRUST_CF_IP=1`, когда origin принимает трафик только от Cloudflare и прокси передаёт проверенный `CF-Connecting-IP`. без этого режима лимит считается по адресу соединения. GET отдаёт доску, POST принимает json с полем `token` и необязательным `nickname` длиной до 24 символов.

## регистрация

переведи одну карту в BOOTSEL и запусти на компьютере с picotool 2.3.1. укажи ssh-хост или алиас и абсолютный путь к mk1-shell на VDS.

```sh
node server/register-card.mjs board-vds /srv/mk1-shell
```

если подключено несколько устройств, передай `--serial` с серийным номером BOOTSEL нужной карты. `--picotool` задаёт путь к исполняемому файлу. если node на VDS отсутствует в ssh PATH, передай его абсолютный путь через `--remote-node`. утилита передаёт серверу chip id и производный ключ по stdin ssh. для отзыва на сервере передай chip id в stdin команды `node server/admin.mjs revoke`. отзыв удаляет запись с доски.

для проверки на локальной базе запусти из корня mk1-shell в powershell

```powershell
$env:MK1_BOARD_DB = Join-Path (Get-Location) 'build/leaderboard-local/leaderboard.sqlite'
node server/register-card.mjs --local --picotool (Join-Path $env:USERPROFILE '.pico-sdk/picotool/2.3.1/picotool/picotool.exe')
```

## проверка результата

сервер проверяет hmac зарегистрированной карты, декодирует байткод и повторно запускает все присланные задачи. для публикации достаточно одной решённой задачи. на каждую карту хранится лучший результат. любая действительная публикация с непустым ником обновляет его и сохраняет время лучшего результата.

hmac подтверждает ключ зарегистрированной карты. происхождение запущенной прошивки требует отдельной аппаратной цепочки доверия и аттестации.

в каталоге пока две обычные задачи. они дают ноль очков. при равенстве выше результат с меньшим числом инструкций, затем с меньшим числом тактов. страница в mk1-web показывает проверенные метрики.

```sh
node --test server/*.test.mjs
```
