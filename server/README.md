# лидерборд mk-1

сервис проверяет подпись зарегистрированной карты и запускает её программы в wasm, собранном из ядра и `content_gen.c`. нужные версии инструментов: node.js 24 и zig.

## запуск

```sh
install -d -m 700 "$HOME/.local/share/mk1-board"
node server/build-score.mjs
node --test server/*.test.mjs
node server/main.mjs
```

сервис слушает `127.0.0.1:8787`. `MK1_BOARD_PORT` задаёт порт, `MK1_BOARD_DB` задаёт абсолютный путь к sqlite. по умолчанию это `~/.local/share/mk1-board/leaderboard.sqlite`. каталог храни вне корня сайта. запускай сервис и регистрацию с одним путём к базе.

прокси публикует `/mk1/api/leaderboard` с исходным путём. при `MK1_BOARD_TRUST_CF_IP=1` прокси должен устанавливать проверенный `CF-Connecting-IP` для каждого запроса. заголовок Cloudflare можно принимать от его адресов, для остальных соединений прокси подставляет адрес своего клиента. без этой переменной лимит считается по адресу подключения к сервису.

## регистрация

переведи одну карту в BOOTSEL и запусти команду на компьютере с picotool 2.3.1. укажи доверенный ssh-хост с закреплённым ключом в `known_hosts` и абсолютный путь к каталогу бэкенда на сервере.

```sh
node server/register-card.mjs board-vds /srv/mk1-shell
```

если подключено несколько плат, передай `--serial`. ключ передаётся серверу по stdin ssh. cli включает строгую проверку ключа хоста и отключает интерактивное подтверждение. `--picotool` и `--remote-node` переопределяют пути к исполняемым файлам. для отзыва записи передай chip id в stdin команды `node server/admin.mjs revoke` на сервере.

локальный вариант в powershell

```powershell
$env:MK1_BOARD_DB = Join-Path (Get-Location) 'build/leaderboard-local/leaderboard.sqlite'
node server/register-card.mjs --local --picotool (Join-Path $env:USERPROFILE '.pico-sdk/picotool/2.3.1/picotool/picotool.exe')
```

## расчёт и модель доверия

- `GET` возвращает `entries`. `limit` задаёт размер страницы от 1 до 100, `offset` задаёт смещение от 0 до 10000. размер по умолчанию 100. `nextOffset` приходит при наличии следующей страницы. лимит на адрес клиента 120 чтений и 12 публикаций или подтверждений в минуту.
- `POST` принимает json с `token` и необязательным `nickname` до 24 символов. токен публикации может установить первый ник карты. для смены установленного ника требуется свежая подпись карты.
- сервер проверяет hmac, декодирует байткод и заново прогоняет каждую присланную задачу. достаточно одного решения.
- сервер повторно использует результаты проверки одинаковых программ в пределах одного запуска. на одну карту приходится до шести новых проверок в минуту.
- в таблице одна запись с лучшим результатом на карту. сортировка сначала по убыванию очков и решённых задач, затем по возрастанию инструкций, тактов, тиков и времени. текущие задачи дают 0 очков.
- держи ссылку `top` приватно. она содержит программы и служит многоразовым ключом публикации.
- hmac подтверждает ключ карты. для проверки запущенной прошивки нужна отдельная аппаратная цепочка доверия.

## смена ника

оба запроса идут через `POST /mk1/api/leaderboard` с json. раздел относится к картам, у которых уже есть результат.

1. `{"action":"nickname-challenge","token": "…","nickname": "…"}` возвращает `nonce` из 32 строчных шестнадцатеричных символов и нормализованный `nickname`.
2. карта подписывает hmac-sha256 последовательность из ascii `mk1/board-nickname/v1`, байта `0x00`, восьми байт chip id, 16 байт `nonce` и `nickname` в utf-8. карта использует свой существующий ключ hmac.
3. `{"action":"set-nickname","nonce": "…","proof": "…"}` передаёт подпись в виде 64 строчных шестнадцатеричных символов. ответ содержит обновлённый `entry`.

nonce действует до двух минут. успешная проверка обновляет ник и погашает все ожидающие подтверждения этой карты в одной транзакции. отзыв карты удаляет её активные подтверждения.
